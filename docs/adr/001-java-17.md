# Quyết định: Dùng Java 17 thay cho Java 21 ở backend

Ngày: 2026-10-15 · Trạng thái: Chấp nhận

## Bối cảnh

`tech-stack.md` đã chốt Java 21 (LTS) cho backend. Khi dựng `backend/`, môi trường của dự án (máy dev, máy chủ triển khai) chỉ có JDK 17. Spring Boot 3 chạy được trên cả Java 17 và 21.

## Các phương án

| Phương án | Ưu | Nhược |
|---|---|---|
| Giữ Java 21 | Có virtual thread cho I/O chặn trong `judge-worker`, pattern matching cho `switch` đầy đủ | Phải nâng JDK ở mọi môi trường trước khi build hay chạy được |
| Dùng Java 17 | Chạy ngay trên môi trường hiện có, vẫn là bản LTS được Spring Boot 3 hỗ trợ | Không có virtual thread; I/O chặn trong worker phải chạy trên thread pool có giới hạn |

## Quyết định

Dùng Java 17 (`java.version` trong `backend/pom.xml`) vì môi trường hiện có chỉ có JDK 17. Không dùng API chỉ có từ Java 18 trở lên.

## Hệ quả

- `tech-stack.md`, `CLAUDE.md`, agent `backend` và workflow deploy ghi Java 17. `clean-code.md` thay virtual thread bằng thread pool có giới hạn.
- Ít ảnh hưởng tới các service web thông thường. `judge-worker` cần định cỡ thread pool chấm bài theo số luồng ở `system-design.md`.
- Xem lại khi môi trường có JDK 21, hoặc khi đo được `judge-worker` nghẽn vì số luồng chặn. Nâng lên 21 chỉ cần đổi `java.version` và image build.
